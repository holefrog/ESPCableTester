# ESP32 智能单端网线测试仪 (ESP32 Cable Tester)

这是一个基于 ESP32 与 OLED 屏幕的“单端”网线测试仪项目。
它的核心目的是解决传统测试仪必须双端同时看灯的痛点，实现**单人、在单端（近端）**即可精准判定长网线的通断、错线与短路故障。

当前进度：**阶段 1 (基础物理回路测试)**

## 🌟 特性

- **真正的单端测试**：只需在远端插上一个纯物理短接的水晶头（Loopback Plug），所有诊断结果在近端的 OLED 屏幕上一目了然。
- **精准的故障定位**：不只是泛泛地报出短路，屏幕会精确指出是哪一根芯出了问题（例如 `SHT(GND)` 代表绝缘破损对地短路，`SHT(4)` 代表与第 4 芯发生了跨对串线），故障排查宛如开卷考试。
- **内置 TDR 断点定位 (黑科技)**：通过在后台极速捕获微秒级的 RC 寄生电容充电时间，能够在无需任何外围元器件的情况下，精准估算网线长度。如果网线中途断裂，屏幕会独立测算并标出断点距离（如 `15.2 ft`）。
- **极简无按键交互**：复用 ESP32 板载的 `BOOT` 按键实现单位切换与长度校准，校准参数永久固化保存在内部 Flash (NVS) 中。
- **高频防闪烁渲染**：内置状态缓存机制，避免 OLED 屏幕高频刷新导致的撕裂感。
- **安全防烧坏机制**：动态引脚扫描，未处于发射状态的引脚全部强制下拉，杜绝短路大电流。

## 📏 TDR 长度测量与校准

本设备具有极客级别的寄生电容测长功能。由于每块 ESP32 芯片的内部阻抗存在物理公差，首次使用需进行一次校准。
*在正常测线模式下，**短按 BOOT 键**可随时在英尺 (ft) 和米 (m) 之间切换默认单位。*

**校准向导步骤**：
1. **长按板子上的 BOOT 键 2 秒以上**进入校准模式。
2. 屏幕提示 `1. Insert empty plug` 时，请插入一个**没有接任何线的空水晶头**（用于获取真实的 0 米寄生电容基准，并顶开特种母座的短接弹片），然后**短按一次 BOOT 键**。
3. 屏幕提示 `1. Insert 76-inch wire` 时，请拔下空水晶头，换上你准备好的 **76 英寸单头基准空网线**（即另一头剪断悬空，不接任何设备）。插好后，再次**短按一次 BOOT 键**。
4. 屏幕提示 `Saved!` 即代表校准完成，参数已永久存入内存，断电不丢失。

## 🛠️ 硬件清单

1. **ESP32 开发板**: ESP32 DevKit V1
2. **显示屏**: 0.96 寸 I2C OLED (SSD1306)
3. **测试母座**: 标准 RJ45 母座模块（**⚠️ 避坑警告**：务必购买普通的纯物理直通转接板。切勿购买带内部网络变压器线圈的 Magjack，或带机械短接弹片的 RJ48 接口，否则未插线时会引发幽灵短路）
4. **远端短接头**: 普通 RJ45 水晶头（需手工短接内部引脚）

## 🔌 硬件接线指南

### 1. OLED 屏幕 (I2C)

使用 ESP32 板载的默认硬件 I2C 接口：

| OLED 屏幕 | ESP32 DevKit V1 | 说明 |
| :---: | :---: | :--- |
| **VCC** | `3.3V` | 3.3V 供电 |
| **GND** | `GND` | 接地 |
| **SDA** | `GPIO 21 (D21)` | I2C 数据线 |
| **SCL** | `GPIO 22 (D22)` | I2C 时钟线 |

### 2. 近端 RJ45 测试母座 (Master)

为了确保信号稳定，以下引脚排布避开了所有的 Strapping（影响启动）与 Input Only（仅输入）引脚：

| RJ45 针脚 | 标准线序 (T568B) | ESP32 GPIO | 用途 |
| :---: | :--- | :--- | :--- |
| **1** | 白橙 | `GPIO 13 (D13)` | 测试信号 发射 |
| **2** | 橙 | `GPIO 14 (D14)` | 测试信号 接收 |
| **3** | 白绿 | `GPIO 25 (D25)` | 测试信号 发射 |
| **4** | 蓝 | `GPIO 26 (D26)` | 测试信号 发射 |
| **5** | 白蓝 | `GPIO 27 (D27)` | 测试信号 接收 |
| **6** | 绿 | `GPIO 32 (D32)` | 测试信号 接收 |
| **7** | 白棕 | `GPIO 33 (D33)` | 测试信号 发射 |
| **8** | 棕 | `GPIO 23 (D23)` | 测试信号 接收 |

### 3. 远端回环测试头 (Loopback Plug)

找一个空的水晶头，在内部将引脚**两两短接**：
- **1 ↔ 2**
- **3 ↔ 6**
- **4 ↔ 5**
- **7 ↔ 8**

> 提示：远端无需任何有源芯片，纯物理短接即可。

4. 将 ESP32 插入电脑，点击 Antigravity IDE 底部状态栏上的 **"→" (Upload)** 按钮即可完成全自动编译与烧录。



## 🔮 TDR 测长“黑科技”深度揭秘

本项目的核心亮点是通过普通的 GPIO 实现纳秒级 TDR（时域反射/寄生电容）测长。为了把几十块钱的 ESP32 榨干到极致、媲美上千元的商用网络测试仪，我们在底层动用了三个“黑科技”级别的深度优化：

### 1. Flash Cache 缓存击穿绕过 (解决 80 周期随机跳动)
在早期的测试中，测量数据会出现高达 80 个 CPU 周期的剧烈跳动。这是因为后台 OLED 屏幕刷新等 RTOS 任务会导致 CPU 指令缓存（ICache）被清空。当 CPU 再次调用 Arduino 原生的 `digitalRead()` 函数时，被迫去外部慢速 SPI Flash 里重新读取代码，这一来一回引发了严重的软件延迟。
**解决方案**：我们直接抛弃了原生的 GPIO 库，改用 `REG_READ(GPIO_IN_REG)` 直接读取底层寄存器，彻底绕过了 Flash Cache 带来的不确定延迟。优化后，极端的 80 周期跳动骤降至个位数，数据稳如磐石。

### 2. PVC 介质电吸收预热 (解决 0.25 米巨大的物理误差)
在测试中发现，用 1.93 米的线校准后，连续测试时长度却飘到了 2.19 米。这并非代码 Bug，而是物理学上的“电吸收效应”：网线外皮（PVC 介质）在连续测试的高频脉冲轰击下，残余电荷会导致其充电变慢，使得测得的电容“显得”变大。
**解决方案**：我们在校准流程中加入了“空转预热机制”，强制在采集前连续轰击网线 10 次以上，让校准时的“热态”曲线完美贴合实际运行时的状态，彻底消除了这 0.25 米的物理误差。

### 3. 10 毫秒锁相积分滤波 (彻底压制 50/60Hz 交流电微波)
网线就像一根长天线，极易吸收空间中无处不在的市电辐射（50Hz / 60Hz），导致测量数据出现像水波纹一样的微小抖动。
**解决方案**：我们在底层测量算法中加入了精确的 100 毫秒积分窗口（完美包含 5 个 50Hz 周期或 6 个 60Hz 周期）。通过积分，交流干扰的正负半波被数学上完全抵消，将最后的微小底噪彻底熨平。

### 4. 高阻态全浮空短路探测 (解决复杂串线时的“假接地”误判)
当网线内部发生严重的跨对串线（例如远端 1-2 和 4-5 被测试头短接，而网线中段 1 和 4 破皮串线，导致 4 根线并联在一起）时。常规测试仪在排查其中一根线是否接地时，其他 3 根线的下拉电阻会并联发力，将探测电压死死拽到 1.1V 以下，导致微控制器误判为“线缆接地（SHT(GND)）”。
**解决方案**：我们在底层加入了瞬态的“全浮空探地”机制。在进行探地检测的那几个毫秒内，强制关闭其余所有针脚的内部下拉电阻，使其处于绝对的高阻态（INPUT）。彻底剥离了复杂网络里的“拉力干扰”，哪怕 8 根线全部拧在一起，只要没碰金属外壳，系统也能精准还原出串线真相（如报出 `1-2 SHT(4)` 和 `4-5 SHT(1)`），绝不误报接地。

## ❓ 常见问题 (FAQ)

**Q: 为什么没插网线时，屏幕乱报短路和串线（如 `1-2 SHT(4)` 和 `4-5 SHT(1)`），但插上自制测试线却全部 PASS？**
A: 这是因为你买到了带有“机械短接弹片 (Shorting Bars)”的特种母座（常见于电信 RJ48 或 ISDN 接口）。这种母座在未插入水晶头时，内部弹片会发生物理闭合（自动把引脚 1和4，以及 2和5 强行短接）。我们的测试仪极其灵敏且精确，完全真实地向你报告了母座内部物理短接的真实现状。插入水晶头后，塑料外壳顶开了弹片，所以恢复正常。
* **解决办法**：如果你是做普通网线测试仪，请更换为最普通的纯物理 RJ45 直通转接板。绝不能使用任何带变压器线圈（MagJack）或带短接弹片的座子。

**Q: 为什么点击 Upload 烧录时，一直卡在 `Connecting........_____.....` 然后报错？**
A: 这是因为部分 ESP32 开发板的“自动下载电路”未能成功触发。你需要手动进入烧录模式：
1. 点击底部的 **Upload (→)** 按钮开始编译。
2. 当终端出现 `Connecting........_____.....` 提示时，**按住板子上的 `BOOT` (或 IO0) 键不放**。
3. （可选）如果没反应，在按住 `BOOT` 的同时，短按一下另一侧的 `EN` (或 RST) 键。
4. 当看到终端开始显示 `Writing...` 或进度百分比时，即可松开 `BOOT` 键，等待烧录完成。
