# ESP32 智能单端网线测试仪

> 个人业余项目 · ESP32 + 128×64 OLED · PlatformIO

这是一个"单端"网线测试仪——只需在网线远端插上一个物理短接水晶头，近端屏幕即可显示通断状态、错线拓扑图、断点距离估算和历史记录。传统测线仪需要两人站在两端对灯，本设备一人单端操作即可完成全部诊断。

---

## 功能特性

- **真正的单端测试**：远端只需纯物理短接水晶头（无需芯片），所有结果在近端 OLED 一目了然
- **故障精确定位**：精确指出是哪一根芯出问题（`SHT(GND)` = 对地短路，`SHT(4)` = 与第 4 芯串线）
- **TDR 断点定位**：利用线缆寄生电容估算长度，无需外围元器件，精度约 ±5cm
- **图形化错线拓扑**：发生错线时屏幕直接画出交叉走线图，直观显示哪两根线接反
- **历史记录**：最近 10 条测试结果自动保存到 Flash，断电不丢失
- **深度睡眠省电**：闲置 5 分钟自动进入深度睡眠

| 操作 | 效果 |
|------|------|

| 长按（2 秒） | 正常模式→进入设置菜单；菜单内→返回 |

### 设置菜单

长按进入，单击切换选项，双击确认：

| 菜单项 | 说明 |
|--------|------|
| View History | 查看历史记录（单击翻页） |
| Clear History | 清空所有历史记录 |

| Calibrate | 启动校准向导 |
| Exit | 返回测量模式 |

### 校准向导

首次使用或更换线缆类型时需校准（约 2 分钟）：

1. 长按进入设置菜单 → 双击 **Calibrate**
2. 屏幕提示 `Insert empty plug` → 插入空水晶头 → **单击确认**
3. 屏幕提示 `Insert 76-inch wire` → 换上 76 英寸（≈1.93m）的单头测试线（另一头剪断悬空） → **单击确认**
4. 屏幕显示 `Saved!` → 校准完成，参数永久存入 Flash

> 校准参数合理范围：350~750 cycles/m。若提示 "Cable too short" 或 "Cable too long"，请检查测试线长度。

## 理解这份代码

> 这一节面向想维护或修改代码的读者。

### 设备做什么（用户视角）

```
你这边（近端）                    远端
┌──────────────┐    一根网线     ┌──────────┐
│ ESP32 + OLED │ ─────────────► │ 短接水晶头│
│  看屏幕结果  │                 │ 每对两两  │
└──────────────┘                 │ 短接      │
                                 └──────────┘
屏幕显示：哪根线断了？哪两根线短路/接错了？线有多长？
```

### 测长度的原理（最难理解的核心）

**一句话**：网线越长，像电容一样充电越慢。

```
ESP32 引脚 ──── 网线 ──── 短接头 ──── 返回 ────┐
   │                                            │
   └────────────── 电容回路 ───────────────────┘

流程：
1. txPin 拉低（提供充电回路的地参考）
2. rxPin 彻底放电到 0V（防止残余电荷影响基准）
3. rxPin 设为高阻态输入
4. 开启 rxPin 内部上拉电阻 → 开始对线缆电容充电
5. 记录 rxPin 电压越过逻辑高阈值需要的 CPU 时钟周期数
6. 周期数 ÷ 校准系数 = 长度（米）
```

这就是为什么需要校准：**用一根已知长度的标准线（76 英寸）告诉设备"这么长对应这么多周期"，它才能计算其他线的长度。**

### 模块分工

```
main.cpp（总指挥）
├── ButtonHandler  → 识别单击/双击/长按，通知 main 发生了什么
├── CableTester    → 执行实际测量，返回 CableStatus 结构体
├── Display        → 把 CableStatus 画到 OLED 屏幕上
```

### 状态机（main.cpp 的核心）

设备任何时刻只处于一个状态：

```
开机未校准
    │ 8秒或任意键
    ▼
STATE_NORMAL ─── 长按 ──► STATE_SETTINGS ─── 双击Calibrate ──► STATE_CALIB_WAIT_EMPTY
（持续测线）                 （菜单导航）                                  │
    ▲                           │                              任意键     │
    │                           │ 双击ViewHistory                        ▼
    └─── 退出/长按 ─────────────►  STATE_HISTORY_VIEW      STATE_CALIB_WAIT_76INCH
                                   （翻页查看历史）                │
                                                              任意键 → 完成校准
```

### 主循环一次测量的流程

```
loop() 每 20ms 执行一次：

1. ButtonHandler::getEvent()  → 有没有按键事件？
2. switch(appState)           → 当前处于哪个状态？
3. 如果是 STATE_NORMAL：
   └─ tester.runTest()
        ├─ detectFullWiremap()   → 扫描 8 根线有无互相短路
        │     把每根针轮流拉高，看其他针有没有跟着高
        │
        ├─ 判断每对线：PASS（通）/ OPEN（断）/ SHORT_OR_CROSS（短路/错线）
        │
        └─ 如果断路 → measureCapacitanceCycles() → 换算成长度
4. display.renderResult()    → 画到屏幕
5. 如果结果有变化 → appConfig.addHistory() → 存 Flash
```

### 代码中三个"为什么这么写"

#### 1. 为什么用寄存器直读而不是 `digitalRead()`？

```cpp
// 普通写法（有问题）：
while (digitalRead(rxPin) == LOW) { ... }
// 问题：digitalRead 在 Flash 里，RTOS 偶尔刷新缓存时
//       这行代码会多花 60-80 个周期 → 测出来长度波动 ±15cm

// 实际写法：
while (((*(volatile uint32_t *)(GPIO_IN_REG)) & pin_mask) == 0) { ... }
// 直接读硬件寄存器，永远 1 个周期，误差降到 ±1cm
```

**简单理解**：`digitalRead` 是打电话问门卫"门开没开"，寄存器直读是自己直接看门。

#### 2. 为什么测 10 次取平均（PHASE_LOCK_SAMPLES）？

```
家用电（50Hz 或 60Hz）会在空气中辐射电磁干扰
网线像天线一样感应到这个干扰 → 测量值一会儿大一会儿小

解决：每次精确等 10ms，连测 10 次，总共 100ms
100ms ÷ 20ms（50Hz 周期）= 5 个完整周期 → 正负抵消
100ms ÷ 16.67ms（60Hz 周期）= 6 个完整周期 → 正负抵消
```

**简单理解**：录音时有嗡嗡的工频噪声，录整数秒后取平均，嗡嗡声就消掉了。

#### 3. 为什么禁用 RTOS 中断（portENTER_CRITICAL）？

```
充电计时期间，如果 RTOS 切换任务（哪怕 1 微秒）：
→ 计时器还在走，充电也在继续
→ 测出来的"充电时间"包含了任务切换的时间
→ 长度算错

所以：
portENTER_CRITICAL()   ← 暂停所有中断，只做这一件事
[充电 + 计时]
portEXIT_CRITICAL()    ← 恢复正常
```

**简单理解**：做精密手术时，把手机调成飞行模式。

## 常见问题

**Q: 没插网线时屏幕乱报 `SHT(4)` 之类的错误，插上测试头又全部 PASS？**

A: 买到了带"机械短接弹片"的 RJ48 特种母座。空载时弹片把引脚 1&4、2&5 强行短接，设备如实报告了这个物理事实。插入水晶头后塑料外壳顶开弹片恢复正常。解决办法：换成最普通的 RJ45 直通转接板。

**Q: Upload 烧录时一直卡在 `Connecting........_____`？**

A: 需要手动进入烧录模式：点击 Upload 后，当终端出现 `Connecting` 提示时，**按住板上 `BOOT` 键**，直到看到 `Writing...` 进度条出现后松开。

**Q: 校准提示 "Cable too short" 或 "Cable too long"？**

A: 校准线长度不对。要求使用 76 英寸（≈1.93m）的单端线（另一头剪断悬空，不接任何设备）。太短（< ~0.7m）或太长（> ~2.1m）都会被拒绝以防止错误校准数据写入 Flash。

**Q: 为什么测出来的长度和实际有偏差？**

A: 首先确认已完成校准。如果已校准但仍有偏差：
1. 校准线和被测线的介质是否一致（CAT5e 和 CAT6 的传播速度因子略有不同）
2. 被测线是否在强电磁干扰环境中（靠近变压器、大电机等）
3. 串口打开监视器，查看 `[DEBUG]` 输出的原始周期数是否稳定

## 两个核心算法详解

### 一、锁相积分——如何消除市电干扰

#### 问题：测量值为什么会抖动？

家用墙壁里的电线时刻在传输 220V 交流电（50Hz 或 60Hz）。这个电流会向空气里辐射电磁波，就像一个很弱的广播台。网线就像一根天线，会感应到这个电磁波。

结果：每次测量的充电时间都会被这个干扰叠加一个微小的波动，导致测出来的长度一会儿大一会儿小，差异约 ±5~10cm。

#### 解决：用时间积分"抵消"干扰

交流电的特性是**正弦波**：上半周期是正值，下半周期是负值，一个完整周期内正负完全对称，加起来等于零。

```
交流干扰波形（50Hz，周期 20ms）：
    ___         ___
   /   \       /   \
──/─────\─────/─────\──► 时间
          \_/         \_/

如果我们的测量窗口 = 恰好 1 个完整周期（20ms）：
正半周影响 +Δ，负半周影响 -Δ，平均后 = 0 ✓
```

**代码里怎么做的：**

```
每次测量 = 10 个采样，每个采样精确等待 10ms

10 次 × 10ms = 100ms 总窗口

100ms ÷ 20ms（50Hz 周期）= 恰好 5 个完整周期  ✓
100ms ÷ 16.67ms（60Hz 周期）= 恰好 6 个完整周期 ✓

10 次采样求平均 → 干扰的正负波动互相抵消 → 结果稳定
```

**生活类比：** 你要测一段路在车流中的噪音。每次单独测量都受到某辆车驶过的影响（忽高忽低）。但如果你连续测量整整 1 分钟再取平均，车流的影响就基本消掉了——因为有车就有没车，有噪音就有安静，长期平均趋向真实值。

"锁相"的意思是：**测量窗口的长度被精确锁定在干扰周期的整数倍**，不是随机取平均，而是数学上精确抵消。

### 二、贪心算法——如何看懂错线

#### 问题：错线时屏幕怎么画那张图？

正常情况：远端回环头按照标准接法短接（1↔2，3↔6，4↔5，7↔8）。

出错情况：假设有人把网线压制时把 1 和 7 两根线接反了：

```
近端                    远端
 1 ──────────────────── 7 ─┐
 2 ──────────────────── 8 ─┘（本来 1↔2 变成了 7↔2）

 7 ──────────────────── 1 ─┐
 8 ──────────────────── 2 ─┘（本来 7↔8 变成了 1↔8）
```

设备在近端测量只能知道：**1 和 7 导通了，2 和 8 导通了**（因为远端它们被短接在一起）。但屏幕上要画出一张图，显示"近端的 1 连到了远端的 7，近端的 7 连到了远端的 1"，需要推理出这个交叉关系。

#### 解决：贪心算法两步推导

**已知条件（硬件事实）：**
- 远端水晶头内部固定是：1↔2，3↔6，4↔5，7↔8（四对环回）
- 近端测到的连通关系（shortNets）：哪几根线属于同一个导通网络

**第一步：找"完美匹配"的正常线对**

逐一检查：近端的 1 和 2 是不是只有它们俩导通？如果是，说明这对线接对了，直接画垂直线（不交叉）。

```
近端 1 ──┐    ← 垂直线，表示正常
近端 2 ──┘
```

**第二步：处理剩余"异常"网络（贪心策略）**

对于没被第一步匹配到的线，找一个"至少有一个引脚在这个网络里"的远端环回，把它们对应上去。

贪心的意思是：**每次只看当前最合理的选择，不回头**。优先把共享引脚的线对匹配在一起（这样画出来的交叉线最少最清晰），剩下的依次分配给还没用的远端环回。

**以 1 和 7 接反为例：**

```
第一步：扫描所有连通网
  网络A：近端 1 和 7 导通（正常应该是 1和2，但现在是 1和7）
  网络B：近端 2 和 8 导通
  → 不是"完美的两端对应"，都属于异常

第二步：贪心分配
  网络A（含1和7）→ 找一个含有 1 或 7 的远端环回
    → 远端有 1↔2 和 7↔8 两个环回
    → 优先选 7↔8（因为 7 在这个网络里），贪心！
    → 画线：近端1 → 远端7，近端7 → 远端8（ 发生交叉 = 错线 ）

  网络B（含2和8）→ 剩下 1↔2 这个远端环回
    → 画线：近端2 → 远端1，近端8 → 远端2（也交叉）
```

**最终屏幕画出：**

```
近端  1  2  3  4  5  6  7  8   ← 上排数字
      │  │  │  │  │  │  │  │
      │  └──┼──┼──┼──┼──┼──┘  ← 交叉线（代表接错）
      └─────┼──┼──┼──┼──┘
            │  │  │  │
近端  1  2  3  4  5  6  7  8   ← 下排数字（远端视角）
```

看到 X 型交叉就知道是哪两根线接反了。

**为什么叫"贪心"？**

因为算法不会尝试所有可能的组合（那样会很慢），而是每步只取当前看起来最合理的选择，不会回头重新考虑。对于网线这种最多 8 根线的场景，贪心策略已经能给出足够准确的拓扑图，无需更复杂的算法。

### 三、Flash 读写——数据怎么断电不丢

#### 物理结构

ESP32 的 Flash 芯片（4MB）被划分成几个区域：

```
Flash 4MB
├── Bootloader       0x01000  ← 启动程序，不能动
├── Partition Table  0x08000  ← 分区表，不能动
├── 固件（你的代码）  0x10000  ← 编译后烧录进去的程序
└── NVS              另一分区  ← 专门存用户数据，断电不丢
```

**NVS（Non-Volatile Storage）** 是厂家划出来专门存"用户变量"的区域，用的是**键值对（Key-Value）**方式存储，类似一个字典。

#### 代码用的是 `Preferences` 库

这是乐鑫官方提供的封装库，让 NVS 读写变得很简单。本项目用了两个命名空间：

```
命名空间 "cable_test"（存校准参数和偏好设置）
├── "b0" → 142000   第1对线的空载基准周期数
├── "b1" → 138500   第2对线的空载基准周期数
├── "b2" → 145000   ...
├── "b3" → 139000   ...
├── "p0" → 520      第1对线每米周期增量（校准系数）
├── "p1" → 515      ...
├── "p2" → 518      ...
├── "p3" → 512      ...
├── "useFeet" → true
└── "soundOn"  → true

命名空间 "cable_history"（存历史记录）
├── "hCount" → 5         当前有多少条记录
└── "hLogs"  → [字节流]  10条 CableStatus 结构体的原始二进制
```

#### 读取一次校准数据的完整流程

```cpp
prefs.begin("cable_test", true);    // 打开命名空间，true = 只读

isCalibrated = prefs.isKey("b0");   // 检查 "b0" 存不存在
                                    // 不存在 → 从来没校准过

for (int i = 0; i < 4; i++) {
    char key[4];
    sprintf(key, "b%d", i);         // 生成 "b0", "b1", "b2", "b3"
    base[i] = prefs.getUInt(key, DEFAULT_BASE_CYCLES);
    //                       ↑ 第二个参数是默认值：key 不存在时用这个
}

prefs.end();                        // 必须关闭！否则其他地方无法打开
```

#### 历史记录用二进制整块存储

校准参数一个个 key 存（8 个数字）。历史记录有 10 条，每条是个复杂的结构体，不拆分，直接把整块内存序列化成字节流写进去：

```cpp
// 写入：
prefs.putBytes("hLogs", historyLogs, sizeof(historyLogs));
//                       ↑ 指向内存的指针    ↑ 写多少字节

// 读取：
prefs.getBytes("hLogs", historyLogs, sizeof(historyLogs));
//                       ↑ 读到哪块内存      ↑ 读多少字节
```

结构体的原始字节原样写进 Flash，读的时候原样拿回来，非常高效。

#### 一次完整校准保存的调用路径

```
用户完成校准
    │
    ▼
main.cpp → appConfig.saveCalibration(base, perM, tester)
    │
    ├─ prefs.begin("cable_test", false)   打开，读写模式
    ├─ putUInt("b0", 142000)              写第1对基准
    ├─ putUInt("b1", 138500)              写第2对基准
    ├─ ... （共8个 key）
    └─ prefs.end()                        关闭，数据物理写入 Flash
    │
断电 / 重启
    │
    ▼
setup() → appConfig.loadAll()
    │
    ├─ prefs.begin("cable_test", true)   只读打开
    ├─ isKey("b0") → true                发现有校准数据
    ├─ getUInt("b0") → 142000            取回上次的值
    └─ prefs.end()
    │
    ▼
tester.setCalibrationData()              装进 CableTester，测量可用
```

#### Flash 写入寿命

NVS 底层用的是 Flash 擦写，每个扇区约能擦写 **10 万次**。Preferences 库内部有**磨损均衡（Wear Leveling）**机制，会自动轮换写入位置，实际寿命比 10 万次更长。

这也解释了为什么 `toggleUnit()` 要用户主动操作才写 Flash，而不是每次测量自动保存——频繁写入会加速 Flash 磨损。

> 代码位置：`src/AppConfig.cpp`（读写实现），`include/AppConfig.h`（接口说明）。

### 四、物理学 Hack——如何测出“短路点”的距离

普通的电容法 TDR 只能测开路（断线）的距离，因为一旦线缆短路，电容效应消失，电压瞬间变化，无法积分测时。

**问题**：当两根线在中间某处短路时，我们怎么知道短路点有多远？
**解决**：经验法则（并联电容翻倍）。

```cpp
// src/CableTester.cpp 里的黑魔法
if (avgCycles < TIMEOUT_CYCLES) {
    outLength = cyclesToMeters(avgCycles, pairIndex) / 2.0f; 
}
```

**物理原理**：
如果两根芯线在距离 $D$ 处短路（且远端悬空），对近端测试仪来说，等效于把两个容量为 $C$（对应长度 $D$）的电容**并联**在了一起。
因为电容并联容量相加（$C_{总} = C_1 + C_2$），测算出来的总充电时间会翻倍，算出的长度是 $2D$。
此时我们**直接把测出来的长度除以 2**，就能非常近似地得到实际故障点（短接点）的物理距离！

虽然精度可能不如几千块的雷达脉冲 TDR（因为短接处的阻抗变化不完全线性），但在实际排错中，知道短路发生在“约 3 米处”还是“约 20 米处”已经足够救命了。

## 🆚 与商业成品仪器的对比

如果你拿这个设备和几千块的专业测试仪（如 Fluke MicroScanner）对比，在**“断线测长”**和**“错线拓扑图”**的核心体验上，本设备已经完全达到了商业水准。

但作为低成本的 DIY 方案，本设备明确**仅限离线环境使用**（施工布线阶段）。在以下几个方面存在物理限制：

1. **⚠️ 无过压保护（PoE 击穿风险）**
   - **成品**：插到带 48V PoE 供电的交换机上会亮红灯保护。
   - **本设备**：网线直通 ESP32 的 GPIO。如果误插到 PoE 交换机，48V 高压会瞬间烧毁 ESP32 芯片。**绝对禁止在带电设备上测试！**

2. **无法检测屏蔽层（Shield）**
   - **成品**：能测试 STP/FTP 屏蔽网线的金属屏蔽层是否接地完好。
   - **本设备**：RJ45 直通座未引出外壳屏蔽引脚，只能把屏蔽线当成普通 UTP 8 芯线测试。

3. **无寻线音频（Tone Generator）**
   - **成品**：能往网线里打入模拟音频信号，配合“寻线笔”在乱线堆里听声音找线。
   - **本设备**：纯数字测试，无音频发声功能（未来若外接三极管和蜂鸣器可考虑扩展）。

4. **无网络层侦测**
   - **成品**：能读取交换机端口速率（10/100/1000M），甚至通过 CDP/LLDP 获取 IP 和交换机名字。
   - **本设备**：仅限纯物理层（Layer 1）布线连通性测试。
